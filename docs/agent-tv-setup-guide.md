# Samsung Tizen TV setup guide

This guide is a portable checklist for an owner setting up their own Samsung Tizen TV. Menu labels and SDK behavior vary by model, region, firmware and SDK release. Use Samsung's current official documentation as the source of truth. This guide does not authorize an AI assistant or contributor to access a TV.

## Before connecting

You need:

- A Samsung Tizen TV and its normal remote.
- A computer supported by the selected Samsung TV SDK.
- Samsung's official TV SDK, SDB and Samsung Certificate Extension or Certificate Manager.
- Your own Samsung developer account and signing certificates.
- A trusted local network shared by the computer and TV.

Keep the TV's model/firmware, network address, DUID, app IDs, certificate profile, signing files and recovery state in private local storage. Do not publish these details or send account passwords/verification codes to an AI assistant. Let the account owner complete sign-in directly in Samsung's official UI.

## 1. Record the target locally

Read the model and full software version from the TV's About This TV screen. Enable Developer Mode only by following Samsung's current instructions for that model. Configure the developer host using the computer's current local address. If the TV does not accept the connection, follow Samsung's documented restart guidance rather than disabling security controls.

Use SDB from the official SDK. Confirm that the intended target appears in `sdb devices` and reports `device`. Record target-specific facts privately. Do not use a hard-coded address or device ID copied from another project or online guide.

## 2. Create your own certificate profile

Use Samsung's [official certificate creation guide](https://developer.samsung.com/smarttv/develop/getting-started/setting-up-sdk/creating-certificates.html). Create an author certificate and the Samsung TV distributor certificate required for your own target. The distributor certificate may require the TV's DUID; select the connected TV in the official wizard when supported, or enter the identifier locally after verifying it on the TV.

The account owner should complete Samsung sign-in and enter passwords or verification codes directly. Keep the resulting profile, private key and certificate files private. Never commit them or paste them into a chat. Save a secure backup separately from the project.

## 3. Configure CleanFrame locally

Copy `signing.example.json` to `.local/signing.json`. Replace each placeholder with the SDK path, certificate profile and package/application IDs generated by your official project tooling. Keep local settings in `.local/`; this directory is ignored by Git. Do not edit tracked app identity just to accommodate a private signing profile unless the change is intended for all contributors.

The repository's Python packaging runner relies on POSIX process and terminal APIs and is documented for macOS/Linux. Windows users need a separately adapted and verified packaging runner. Do not assume that installing Tizen Studio alone makes the current runner portable to Windows.

## 4. Build and verify

Run the documented source checks first. Build with Samsung's official packaging/signing tools. Review the command result and generated package locally. Verify that:

- The widget contains the expected `config.xml` and application identity.
- Samsung author and distributor signatures are present and valid according to the SDK.
- The distributor certificate authorizes the actual target TV.
- The WGT contains no private keys, password files, device config or local build output.

Keep the signed package out of Git. An unsigned public export is for source distribution or inspection and is not ready to install.

## 5. Install and launch only with owner approval

Before install, confirm SDB connectivity again, confirm the intended target state is `device`, and resolve the exact package path and application ID. Follow Samsung's current official TV installation workflow, including Device Manager authorization required by the SDK. Do not assume `sdb install` is equivalent to Samsung TV app installation on every SDK/TV combination.

Only the TV owner can authorize installing or launching a specific build. Stop on any error and report the exact safe diagnostic. After successful installation, verify the TV's installed-app list and launch using the actual application ID. Have the owner confirm the visible result and test D-pad, OK, Back and Home behavior. Do not intercept system-reserved shortcut, volume, power or voice controls.

## Unsupported operations

Routine app setup does not require replacing Smart Hub, changing startup/Home assignments, removing system apps, rooting the TV, bypassing security or modifying firmware. Experimental scripts under `scripts/native-home/` use undocumented, target-specific behavior and are not a portable install method. Do not run them without a separate explicit owner request, target-specific technical review and confirmed recovery route.
